## T2.7 — the threshold, derived from that distribution

Admission CDF on the post-T2.6 nearest-neighbour distribution:

| threshold | admitted as novel |
|---:|---:|
| 3 | 89.4% |
| **4** | **75.2%** ← new base (the measured p25) |
| 5 | 52.7% (old base) |
| **6** | **29.1%** ← new same-family (4 + margin 2) |
| 8 | **5.6%** (old same-family, 5 + 3) |

Hard is 72% geometric-lattice, so the **same-family** threshold is the one that
usually applies — and at 8 it admitted 5.6%. That is not a strict gate, it is
an unreachable one.

**The floor this cannot cross.** The margin exists so pure silhouette hopping
cannot read as novelty. Within a visual family the family bits are identical,
so a silhouette-only difference is at most **3** bits (computed over all
same-family pairs; `diamond`↔`cross` is 1). A same-family threshold of 6 keeps
double that headroom.

`hammingThreshold` 5 → **4**, `sameVisualFamilyHammingMargin` 3 → **2**.

## 4. Blocker — relay soft-locks are now reachable on the campaign

`autoplay_600_test` went red: **4 stranded play-throughs of 1,800**, on
`medium L501` (3 of 3 routes) and `hard L592` (1 of 3).

Both boards contain a relay:

```
medium L501: 22 nodes 9x9  {normal: 19, locked: 2, relay: 1}
hard   L592: 25 nodes 8x8  {normal: 22, locked: 2, relay: 1}
```

This is **not a new defect**. It is the same one
`relay_softlock_property_test` has been failing on since before P1, and which
the solvability invariant says relays are the only source of. What changed is
that selection now ships different boards, and two of them are reachable dead
ends — so the defect has moved from "latent, caught only by a property test" to
"a player can tap into it on the shipping campaign".

**Consequence: the relay soft-lock fix is promoted from a pre-freeze to-do to a
P2b blocker.** It must land before the re-baseline, not after — re-pinning a
corpus that contains soft-lockable boards freezes them in.
